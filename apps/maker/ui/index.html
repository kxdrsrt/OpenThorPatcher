Publish your client

Keep one master client up to date. The Patch Maker compares it with what you published last time and writes only the difference: numbered Thor patches for big GRFs, whole files for small ones, a signed patch list. Players update from that.

The master client is the folder you maintain. The patch site is a folder the Patch Maker writes; you upload it to your host.

Signing key

Players check every patch list against your public key, so nobody else can send them files. The secret key stays on this computer.

Options

Decide how each file reaches players. Patch entries is for big GRFs: only the files inside that changed are sent. Sync whole sends the file again when its hash changes (good below ~50 MB). Ignore keeps it out.

Paths deleted from every player's client on the next update. Use folder/* for a whole folder. Files inside a GRF are removed by simply deleting them in the master GRF; the next publish sends a delete.

Paths are relative to the client folder. Anything outside it is refused.

Maintenance

Players download from your mirrors. Any static host works: your own server, S3 / Cloudflare R2, GitHub Releases. Cloud drives (Google Drive, Dropbox, OneDrive) give every file its own share link; paste them below.

Mirrors

The first mirror is tried first; the others are used when it fails. Folder structure of the site is kept (files/…, patches/…).

Cloud links

Cloud drives are the fragile option. Large files can hit download quotas or return a web page instead of the file; the patcher then stops with a clear message. Use them for small communities, and prefer a static host for anything big. Links are converted to direct downloads automatically.

Player config
