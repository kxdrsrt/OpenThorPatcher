Publish your client

Keep one master client up to date. The Patch Maker compares it with what you published last time and writes only the difference: numbered Thor patches for big GRFs, whole files for small ones, a signed patch list. Players update from that.

The master client is the folder you maintain. The patch site is a folder the Patch Maker writes; you upload it to your host.

Signing key

Players check every patch list against your public key, so nobody else can send them files. The secret key stays on this computer.

Options

OdinGuard Anti Cheat

Optional. After each publish the GRFs of the master client go into your OdinGuard profile (og grf-scan, older versions stay accepted) and grf-manifest.json goes into the site; the patcher then tells players when a GRF is not a version the server accepts. Needs the og program. Rebuild and deploy the server config before players patch.

Patcher self-update

Optional. Players' patchers replace themselves with these builds before they patch (only with a signed list). Raise the version with every new build.

Decide how each file reaches players. Patch entries is for big GRFs: only the files inside that changed are sent. Sync whole sends the file again when its hash changes (good below ~50 MB). External link is for huge base files such as data.grf: only its hash and your download links (MEGA, a release, your server) go into the list, the file itself is never uploaded with the site. Ignore keeps it out.

Paths deleted from every player's client on the next update. Use folder/* for a whole folder. Files inside a GRF are removed by simply deleting them in the master GRF; the next publish sends a delete.

Paths are relative to the client folder. Anything outside it is refused.

Theme

The patcher's look is a folder patcher-theme/ in the client: theme.json, theme.css, a logo and fonts. Export the built-in "Midgard Night" theme, change it, and put the folder into the master client; the Files page then syncs it to players like any other file.

Players download from your mirrors. Any static host works: your own server, S3 / Cloudflare R2, GitHub Releases. Cloud drives (Google Drive, Dropbox, OneDrive) give every file its own share link; paste them below.

Mirrors

All mirrors must hold the same site (upload every publish to each of them). The first is tried first; if it is down or behind, the player's patcher reads the patch list from the others too and takes the newest one, and every file is checked by its SHA-256, so only the master version is ever installed. They are written into patcher.json as fallback_urls. Folder structure of the site is kept (files/…, patches/…).

Cloud links

Cloud drives are the fragile option. Large files can hit download quotas or return a web page instead of the file; the patcher then stops with a clear message. Use them for small communities, and prefer a static host for anything big. Links are converted to direct downloads automatically.

Upload

One target per line. rclone destinations (remote:path, set up once with rclone config: SFTP to your own server, S3 / R2, MEGA, Google Drive, Dropbox, OneDrive) or a local folder; for packages and external files also gh-release:owner/repo@tag (needs the gh program). The site is uploaded file by file and the patch list last, so players never see a half-uploaded site; state/ stays on this computer.
